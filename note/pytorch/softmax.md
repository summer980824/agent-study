## Q1: Softmax 的目的是什么？

Softmax 把一组任意实数转换成**和为 1、每项都为正的概率分布**：

$$\text{softmax}(x_i) = \frac{e^{x_i}}{\sum_j e^{x_j}}$$

```python
def softmax(x):
    exp_x = torch.exp(x)
    return exp_x / exp_x.sum(dim=-1, keepdim=True)
```

两步各有分工：

- **取指数** `torch.exp(x)`：$e^x > 0$ 保证结果为正，才能当概率；同时 $e^x$ 增长迅猛，会**放大输入间的差距**——输入 2.0 和 1.0 只差 1，取指数后 7.39 是 2.72 的 2.7 倍，概率份额从"各占一半"变成 0.66 vs 0.24。这就是"软性的 max"：最大值拿最大份额，但其他值也分到一点（可导，能反向传播）。
- **除以行和**：归一化，让每项落在 $[0,1]$ 且总和为 1。

```python
x = torch.tensor([2.0, 1.0, 0.1])
softmax(x)   # tensor([0.6590, 0.2424, 0.0989])，相加 = 1.0
```

在 Transformer 注意力里，softmax 把 `Q @ K.T` 算出的原始分数（可正可负、任意大小）变成**注意力权重**：每个 token 对所有 token 的关注程度加起来等于 1，之后才能对 V 做加权求和。

输入差距越大，输出越接近 one-hot（赢家通吃）；输入全相等时输出均匀分布。另外 softmax 有**平移不变性**：所有元素加减同一常数，结果不变——这是 Q3 数值稳定技巧的基础。

## Q2: dim=-1 和 keepdim=True 的作用？

```python
return exp_x / exp_x.sum(dim=-1, keepdim=True)
```

**`dim=-1`：沿最后一维求和**，即对"每一行"独立归一化。

对注意力分数 `scores [batch, seq_len, seq_len]`，`dim=-1` 表示：每个 token 的那一行分数（它对序列里所有 token 的打分）单独做 softmax，得到"这个 token 的关注分配"。batch 维和 query 维都不动。

```python
scores = torch.randn(2, 3, 4)
attn = softmax(scores)
attn.sum(dim=-1)   # 全为 1.0，shape [2, 3]——每行和为 1
```

**`keepdim=True`：求和后保留维度**，让结果形状为 `[2, 3, 1]` 而不是 `[2, 3]`。

这是为了除法时能正确**广播**：`[2, 3, 4] / [2, 3, 1]` 广播成"每行除以该行的和"。如果不加 `keepdim=True`，`[2, 3, 4] / [2, 3]` 维度对不上，直接报错（或广播到错误的方向）。

一句话：**`dim=-1` 决定"对哪一组数归一化"，`keepdim=True` 让除法按行广播。**

## Q3: 为什么 Softmax 计算时经常减去最大值？

为了**防止指数溢出（overflow）和下溢除零**，实际写法是先减去每行最大值：

```python
def stable_softmax(x):
    shifted = x - x.max(dim=-1, keepdim=True).values
    exp_x = torch.exp(shifted)
    return exp_x / exp_x.sum(dim=-1, keepdim=True)
```

**为什么不改结果？** 平移不变性——分子分母同乘 $e^{-c}$，约掉：

$$\frac{e^{x_i - c}}{\sum_j e^{x_j - c}} = \frac{e^{x_i}}{\sum_j e^{x_j}}$$

所以 `stable_softmax([1000, 1001, 1002])` ≡ `softmax([-2, -1, 0])` ≡ `softmax([1, 2, 3])`，数学上结果完全相等，实际浮点计算允许存在微小误差。

**不减最大值会出什么事？**

浮点数容量有限：float32 最大约 $3.4 \times 10^{38}$（对应 $e^{88.7}$），float64 最大约 $1.8 \times 10^{308}$（对应 $e^{709.8}$）。

| 输入 | 不减最大值 | 减最大值后 |
|---|---|---|
| 大正数 `[1000, 1001, 1002]` | $e^{1000}$ 上溢成 `inf`，`inf/inf = nan` | 平移成 `[-2, -1, 0]`，exp 结果 ∈ (0, 1]，正常 |
| 大负数 `[-1000, -1001, -1002]` | $e^{-1000}$ 下溢成 0，分母为 0，`0/0 = nan` | 平移成 `[0, -1, -2]`，分母 ≥ 1，正常 |

减最大值后：

- 最大元素恒为 0，$e^0 = 1$ 是指数的上限，**远离溢出**。
- 其余元素都是负数，$e^{负数} < 1$，**更安全**（softmax 怕的是大正数，不是负数）。
- $e^0 = 1$ 恒在分母里，**分母恒 ≥ 1，不会除零**；极负元素下溢成 0 也没关系——它的真实概率本来就约等于 0。

**减最大值救不了的一种情况**：输入本身精度已丢失。float32 只有约 7 位有效数字，在 $10^{10}$ 量级相邻可表示数间隔约 1024，`[1e10, 1e10+1, 1e10+2]` 存进 tensor 时就可能变成同一个数，softmax 无法找回丢失的差值。

实际项目直接用 `torch.softmax(x, dim=-1)`（内部已做稳定化处理）；注意力里还有配套的 `scores / math.sqrt(d_k)` 缩放，防止点积随维度增大把 softmax 推进饱和区（梯度趋近 0）。
